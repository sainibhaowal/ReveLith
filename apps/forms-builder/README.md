# ReveLith Forms Builder

Forms Builder is a local-first ReveLith editor for creating `.form.json` documents. It includes text, choice, contact, file/signature, full-name, date-range, country, picture-choice, legal-consent, input-table, hidden-value, content-screen, and nested question-group fields; field validation and conditional visibility; branching, calculated variables, scored quizzes, randomized choices, per-choice image/icon/color styling and layouts; HTTPS image/video field media with brightness, placement, and background controls; manually authored translations including choice labels and custom BCP 47 tags; bundled offline respondent messages for English, German, Spanish, French, Italian, Portuguese, Hindi, Japanese and Arabic; locale-aware number/date formatting; respondent-flow and UTC opening/closing schedules; themes; local preview drafts and responses; formula-neutralized CSV and JSON response exports; submission-only local response summaries; shell save/open/autosave; and a ReveLith AI panel with form editing and web-search tools when opened inside the ReveLith shell. The response panel supports local search, full-answer inspection, quiz-score review, individual deletion, clearing, and importing responses returned by offline forms. Uploaded response files are inspected against recognizable content signatures, stored as local IndexedDB blobs and downloadable from response details. JSON response packages include the actual bytes for referenced files (up to a 100 MB total package); they remain on this device unless the user moves the export.

For each Chat turn, a local intent router selects the form tools relevant to that request before contacting the configured model. A clear single operation can send one tool definition; multi-step requests can send a related set; ordinary chat sends no form-editing tools. Ambiguous editing requests retain the full set to avoid blocking an operation the router cannot safely classify. Tool input is still validated by each handler. `e2e/forms-builder-all-tools.spec.ts` exercises all 17 handlers through the ReveLith Chat transport and checks that a straightforward field request exposes only `add_form_field`.

The selected-field **Ask AI** action sends only a bounded, allow-listed field definition and editor bounds, excludes responses/answers and attachments, and disables tools. It refuses cloud or unknown model endpoints; selected field data is sent only to an explicitly configured loopback-local endpoint. The Help ribbon shows the count of its registered save/undo/redo shortcuts.

Untitled forms are saved to a local recovery copy as you edit. Reloading the same form tab restores that copy. A new Forms task still opens blank; if earlier unsaved drafts exist, the builder offers Restore or Delete copy. Saving a named `.form` file enables file autosave when AutoSave is on. Local recovery is device-specific and is not a substitute for exporting or backing up a file.

The respondent preview exposes built-in UI translations and form-authored translations. The translation editor can generate authored labels, choices, descriptions, and messages with a configured local LM Studio, Ollama, or loopback custom model; it refuses remote model endpoints and leaves the source language untouched. Formatters use the browser's bundled `Intl` locale data. Uploads check recognizable signatures; DOCX/XLSX/PPTX/ODT/ODS/ODP files are checked for package manifests and required document parts, and the main XML parts' CRCs are verified with bounded size checks. In the ReveLith Windows shell, uploads are also scanned by Microsoft Defender before acceptance; if Defender is absent, unavailable, or reports an error, the upload is rejected. This is device antivirus scanning, not a guarantee against every threat, and the standalone Forms Builder outside the shell does not have the Defender bridge.

The single-file Offline HTML export embeds the form and a hash-locked runtime, stores responses locally in the browser, and lets respondents download a response JSON package with attached file bytes. The form author can import that JSON into the matching form to collect responses without a hosted service. The runtime supports page breaks, one-question flow, conditional visibility, navigation and calculation rules, quiz scoring, and secure HTTPS field/choice media when a network is available; data-embedded images work offline. It includes a local iframe snippet. Some advanced settings and field-specific behavior can still differ from native preview, so review and test the exported HTML before distributing it.

Accessible names and descriptions are added to respondent controls, validation errors are announced, focus indicators are visible, and completion moves focus to its heading. The standalone export E2E runs axe-core and currently expects zero reported violations, and the flow checks keyboard page navigation. A full human screen-reader and assistive-technology audit across the authoring UI, all field types, languages, themes, and operating systems is still required.

Form drafts and preview submissions are stored locally. Offline response JSON can be moved between devices and imported into the matching form. This does not create a hosted public URL or a central response service. The app does not provide HeyForm's hosted account, tenant, payment, publishing, or integration services. External HeyForm packages were reviewed only as product references; this app does not depend on or copy their implementation.

Legacy form files are normalized when opened. The current schema version is `1`; unknown top-level extension properties are preserved. The normalizer rejects malformed fields, duplicate IDs, unsupported field types, oversized choice lists, unsafe validation patterns, invalid rules, and invalid field/variable references.

This is not full feature parity with a hosted form platform. Team accounts and permissions, hosted publishing, CAPTCHA verification, payment processing, remote uploads, email delivery, integrations/webhooks, and third-party embed endpoints need separately designed and secured services. The app does not present those capabilities as working local controls.
